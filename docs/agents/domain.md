# Domain documentation

Keeply is a single-context project. `CONTEXT.md` is the existing domain vocabulary. Read it alongside `docs/HANDOFF.md` before terminology or product decisions.

For the upstream domain-modeling skill, use `CONTEXT.md` wherever it refers to `GLOSSARY.md`; do not create a competing glossary. Record newly resolved terms there. Record significant architectural tradeoffs in `docs/adr/` only when decisions justify it. Do not create empty ADRs or turn vocabulary into a task log.
